# A5.4 — Cross-turn Information Persistence & State Updating

## Boundary

A5.4 is a cross-turn Information-Seeking capability, not a survey of Agent Memory architectures. Memory is treated as an implementation substrate and evaluation setting. The capability question is:

> **Can LLMs learn to persist, revise, and reuse acquired information across interactions without accumulating stale, conflicting, or irrelevant memories?**

The four cross-cutting dimensions are:

- **A5.4.1 Selective Information Persistence:** what acquired information should survive the current turn, and can the system avoid indiscriminate retention?
- **A5.4.2 Cross-turn State Revision:** can new information overwrite, merge, invalidate, or preserve prior state correctly under time changes and conflict?
- **A5.4.3 Future Information Utility:** does persisted information produce measurable later-task benefit, and can that benefit be attributed to the persisted state rather than fresh retrieval, context leakage, or parametric knowledge?
- **A5.4.4 Persistence Policy Learning:** do SFT, RL, feedback, or another learning signal teach transferable write, update, delete, no-op, and utilization behavior?

Every paper is also coded with **Persistence Target** (`External Memory`, `Context State`, `Policy`, or `LLM Parameters`), **Temporal Consistency**, **Future Utility Attribution**, and **Memory Failure Type**: `Write Failure`, `Update Failure`, `Retrieval Failure`, or `Utilization Failure`.

The strongest proposed comparison is:

> **No Persisted State → Actual Persisted State → Oracle State**

with key-memory deletion, replacement, time-order, preference-change, stale-memory, conflict, and memory-leakage interventions. None of the six papers provides this complete causal ladder.

## A5.4.1 / A5.4.2 Measurement resources

### M1. LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory

- **Authors / year:** Di Wu, Hongwei Wang, Wenhao Yu, Yuwei Zhang, Kai-Wei Chang, Dong Yu, 2025.
- **Venue / links:** ICLR 2025 Poster; [official proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d813d324dbf0598bbdc9c8e79740ed01-Abstract-Conference.html) · [arXiv](https://arxiv.org/abs/2410.10813) · [code](https://github.com/xiaowu0162/LongMemEval)
- **Role / contribution:** Core / Evaluation
- **Primary dimension:** A5.4.2 Cross-turn State Revision
- **Secondary dimensions:** A5.4.1 Selective Information Persistence; A5.4.3 Future Information Utility
- **Persistence target:** External Memory
- **Memory failure labels:** Write Failure, Update Failure, Retrieval Failure, Utilization Failure
- **Selective Information Persistence:** Evaluation-only. The benchmark tests whether systems can recover user or assistant information from single-session, indirect-expression, session, round, and fact-level settings. History is mostly placed into a retrievable collection; there are no salience labels, selective-write targets, or NOOP/delete gold actions.
- **Cross-turn State Revision:** Knowledge-update and temporal-reasoning tasks require newer information and temporal metadata, but the benchmark does not expose an auditable memory state or systematically intervene on stale, conflicting, expired, or replaced facts.
- **Future Information Utility:** The benchmark separates retrieval metrics such as Recall@k/NDCG@k from downstream QA and provides full-history, retrieval-pipeline, and oracle-evidence conditions. These are the closest approximation in the batch to No Persisted State → Actual Persisted State → Oracle State, but retrieval, reader prompts, time cropping, context leakage, and parametric knowledge remain confounded.
- **Temporal consistency:** Partial. Sessions are time-ordered and time-aware query expansion is evaluated. There is no systematic arbitrary order permutation, preference replacement, expiry, conflict-ratio, or selective-forgetting test.
- **Future utility attribution:** Partial, not causal. Oracle evidence and retrieval metrics provide useful decomposition, but later-task improvements cannot be attributed uniquely to persistence rather than retrieval or reading.
- **Memory policy learning:** None. No SFT, DPO, PPO, GRPO, or feedback learning; round decomposition, fact-augmented keys, time-aware expansion, and Chain-of-Note are hand-designed or prompted pipelines.
- **Evidence vector:** `Method Effectiveness: Strong`; `Capability Isolation: Medium`; `Generalization Evidence: Medium`.
- **Main limitation:** Write, update, retrieval, and utilization failures are mixed inside a retrieval–reading–answering chain. There is no operation-level state trace, memory-action supervision, or transferable policy evaluation.
- **Decision:** Include Core as an A5.4 measurement anchor, not a learning method.

### M2. MemoryAgentBench: Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions

- **Authors / year:** Yuanzhe Hu, Yu Wang, Julian McAuley, 2026.
- **Venue / links:** ICLR 2026 Poster; [official proceedings](https://proceedings.iclr.cc/paper_files/paper/2026/hash/fd1eff9dd295df50a41f2521942fa31d-Abstract-Conference.html) · [OpenReview](https://openreview.net/forum?id=DT7JyQC3MR) · [arXiv](https://arxiv.org/abs/2507.05257) · [code](https://github.com/HUST-AI-HYZ/MemoryAgentBench)
- **Role / contribution:** Core / Evaluation
- **Primary dimension:** A5.4.2 Cross-turn State Revision
- **Secondary dimensions:** A5.4.1 Selective Information Persistence; A5.4.3 Future Information Utility
- **Persistence target:** External Memory and Context State
- **Memory failure labels:** Write Failure, Update Failure, Retrieval Failure, Utilization Failure
- **Selective Information Persistence:** Sequential chunk injection, context growth, external stores, and agentic memory modules test information absorption, but there is no gold write set, write precision/recall, keep/discard annotation, or selective-write/NOOP control.
- **Cross-turn State Revision:** FactConsolidation creates original and newer contradictory facts and tests single- and multi-hop answers; EventQA tests temporal sequences. The benchmark also compares latest-wins and conservative overwrite prompts. These are useful synthetic revision probes, not learned state revision.
- **Future Information Utility:** Later QA, classification, recommendation, narrative reasoning, and summarization are measured after incremental interaction. TTL and full-history settings provide behavioral evidence, but there is no oracle-memory bound or fresh-retrieval and leakage control.
- **Temporal consistency:** Partial. Event order and later contradictory facts are evaluated, but natural preference change, expiry, randomized order, irrelevant updates, and explicit NOOP cases are absent.
- **Future utility attribution:** Limited. Final scores can reflect raw context length, retrieval, in-context learning, reasoning, or parameters rather than a persistent memory representation.
- **Memory policy learning:** None. Test-Time Learning means inference-time rule acquisition, not SFT/RL/feedback learning of a transferable memory lifecycle policy.
- **Evidence vector:** `Method Effectiveness: Strong`; `Capability Isolation: Medium`; `Generalization Evidence: Limited`.
- **Main limitation:** Selective Forgetting uses synthetic serial-number chronology and explicit later-fact rules. The benchmark exposes end-task behavior but not write/update/delete/NOOP traces or causal memory utility.
- **Decision:** Include Core as an A5.4 measurement anchor, not a learning method.

## A5.4.3 / A5.4.4 Persistence Policy Learning and Future Utility

### M3. Memory-R1: Enhancing Large Language Model Agents to Manage and Utilize Memories via Reinforcement Learning

- **Authors / year:** Sikuan Yan et al., 2026.
- **Venue / links:** ACL 2026 Long Paper; [ACL Anthology](https://aclanthology.org/2026.acl-long.583/) · [arXiv](https://arxiv.org/abs/2508.19828) · [code](https://github.com/yansikuan/memory-r1)
- **Role / contribution:** Core / Capability Learning
- **Primary dimension:** A5.4.4 Persistence Policy Learning
- **Secondary dimensions:** A5.4.1 Selective Information Persistence; A5.4.2 Cross-turn State Revision; A5.4.3 Future Information Utility
- **Persistence target:** External Memory, with Memory Manager and Answer Agent policy parameters fine-tuned
- **Memory failure labels:** Write Failure, Update Failure, Retrieval Failure, Utilization Failure
- **Selective Information Persistence:** The Manager chooses ADD, UPDATE, DELETE, and NOOP and proposes updated content. This is substantially beyond unconditional append. However, extraction quality and action correctness have no independent operation-level labels; Manager reward comes from downstream QA.
- **Cross-turn State Revision:** Structured UPDATE, DELETE, and NOOP actions support consolidation of complementary facts and revision of old state. Temporal, stale, expiry, preference, conflict, and selective-forgetting interventions are not systematically evaluated.
- **Future Information Utility:** During Manager training, updated memory is passed to a frozen Answer Agent and downstream QA supplies the reward. Evaluation also reports final QA and zero-shot transfer to MSC and LongMemEval. There is no complete No Persisted State → Actual Persisted State → Oracle State, leave-one-memory-out, fresh-retrieval, or parameter-knowledge counterfactual.
- **Temporal consistency:** Limited. Multi-session dialogue and temporal/knowledge-update categories are present, but stale-memory expiry, preference replacement, order permutation, and natural conflict are not directly controlled.
- **Future utility attribution:** Partial and indirect. The frozen Answer Agent during Manager optimization gives some action-level separation, but final gains remain mixed with retrieval, Answer-Agent adaptation, context leakage, and parametric knowledge.
- **Memory policy learning:** Yes. Memory-R1 is the clearest direct policy-learning paper in the batch. PPO/GRPO update both Memory Manager and Answer Agent policies. This should not be conflated with MemRL, which freezes the base LLM and learns only external-memory utility values.
- **Training–capability alignment:** Partial. The action space aligns directly with memory lifecycle operations, but sparse final-answer EM cannot identify whether a particular ADD, UPDATE, DELETE, or NOOP was correct.
- **Evidence vector:** `Method Effectiveness: Strong`; `Capability Isolation: Limited`; `Generalization Evidence: Limited`.
- **Main finding:** Memory-R1 demonstrates genuine Agent Policy post-training for memory management and utilization, but not a fully verified, transferable memory policy.
- **Main limitation:** No operation-level ground truth, causal memory-ablation ladder, selective-forgetting test, stale/conflict suite, or direct behavior-transfer measurement. The public repository states that code is forthcoming, limiting reproducibility.
- **Decision:** Include Core.

### M4. MemRL: Self-Evolving Agents via Runtime Reinforcement Learning on Episodic Memory

- **Authors / year:** Shengtao Zhang et al., 2026.
- **Venue / links:** arXiv cs.CL preprint; [arXiv](https://arxiv.org/abs/2601.03192) · [code](https://github.com/MemTensor/MemRL)
- **Role / contribution:** Core / Memory System with utility learning
- **Primary dimension:** A5.4.3 Future Information Utility
- **Secondary dimensions:** A5.4.1 Selective Information Persistence; A5.4.2 Cross-turn State Revision; narrow A5.4.4 Persistence Policy Learning
- **Persistence target:** External Memory
- **Memory failure labels:** Write Failure, Update Failure, Retrieval Failure, Utilization Failure
- **Selective Information Persistence:** Each sampled trajectory is summarized into an Intent–Experience–Utility triplet and appended. The system does not learn a write-versus-NOOP gate, quality-based retention, deduplication, or selective deletion.
- **Cross-turn State Revision:** Runtime feedback updates a scalar Q value and changes retrieval ranking. Experience text is not overwritten, merged, reconciled, or expired; there is no conflict or preference revision protocol.
- **Future Information Utility:** This is the strongest focus of MemRL. Semantic recall generates candidates, Q-aware reranking selects memories with higher expected future return, and environmental feedback updates Q values. Held-out instances, cross-backbone transfer, and Q-success correlation provide partial evidence.
- **Temporal consistency:** Limited. Task-level forgetting is reported, but temporal order, stale facts, changing preferences, expiry, and conflicting memories are not directly manipulated.
- **Future utility attribution:** Partial. No Persisted State baselines, non-RL comparisons, held-out transfer, and a reported Q-success Pearson correlation of 0.861 are useful. There is no Oracle State, leave-one-memory-out, fresh-retrieval, context-matched, or process-level causal control, and shared rewards create memory credit-assignment ambiguity.
- **Memory policy learning:** Narrow and partial. The frozen LLM is not post-trained. Runtime RL learns external-memory Q values and an induced retrieval ranking, not a complete write/update/delete/expire/NOOP lifecycle policy.
- **Training–capability alignment:** Partial. Environmental return directly reflects whether retrieved experience helps downstream tasks, but it cannot uniquely credit individual memories or supervise content revision and selection.
- **Evidence vector:** `Method Effectiveness: Strong`; `Capability Isolation: Limited`; `Generalization Evidence: Medium`.
- **Main finding:** MemRL is an important contrast to Memory-R1: it learns memory utility without updating LLM parameters, showing that runtime external-memory learning can improve later task performance.
- **Main limitation:** Utility learning is disconnected from content lifecycle management. Reward hacking, memory pollution, non-stationarity, and shared credit assignment remain concerns.
- **Decision:** Include Core, but do not label it full Persistence Policy Learning.

## Implementation contrasts — not a separate Memory taxonomy

### M5. A-MEM: Agentic Memory for LLM Agents

- **Authors / year:** Wujiang Xu, Zujie Liang, Kai Mei, Hang Gao, Juntao Tan, Yongfeng Zhang, 2025.
- **Venue / links:** NeurIPS 2025 Main Conference; [NeurIPS](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html) · [arXiv](https://arxiv.org/abs/2502.12110) · [code](https://github.com/WujiangXu/A-mem-sys)
- **Role / contribution:** Core / Memory System
- **Primary dimension:** A5.4.2 Cross-turn State Revision
- **Secondary dimensions:** A5.4.1 Selective Information Persistence; A5.4.3 Future Information Utility
- **Persistence target:** External Memory
- **Memory failure labels:** Write Failure, Update Failure, Retrieval Failure, Utilization Failure
- **Selective Information Persistence:** Every incoming interaction is stored as a note with original content, timestamp, keywords, tags, and contextual description. The LLM-generated metadata enriches representation but does not learn what is worth storing; there is no write/no-op gate or irrelevant-memory insertion control.
- **Cross-turn State Revision:** New notes retrieve neighbors and prompt an LLM to generate links and evolved context/tags. This is inference-time metadata/context evolution, not verified factual overwrite, merge, conflict resolution, expiry, or selective forgetting. Manual update/delete APIs are not learned policies.
- **Future Information Utility:** LoCoMo and DialSim QA, link/evolution ablations, top-k sweeps, and token/scaling analyses show system-level gains. They do not isolate causal memory utility from retrieval, generated metadata, prompts, or parametric knowledge.
- **Temporal consistency:** Limited. Timestamps and temporal QA are present, but stale-memory, preference-change, conflict-order, and expiry interventions are absent.
- **Future utility attribution:** Partial but not causal. The closest comparison is full-context/no dedicated memory against A-MEM, not a matched No Persisted State → Actual Persisted State → Oracle State ladder.
- **Memory policy learning:** None. No SFT, DPO, PPO, GRPO, RL, preference feedback, or memory-quality reward updates an Agent Policy.
- **Evidence vector:** `Method Effectiveness: Strong`; `Capability Isolation: Limited`; `Generalization Evidence: Limited`.
- **Main finding:** A-MEM demonstrates useful external-memory organization and prompted metadata evolution, not learned transferable memory management.
- **Main limitation:** All-interaction storage and prompt-based evolution leave write correctness, stale/conflict state, selective forgetting, and future utility attribution unresolved.
- **Decision:** Include Core as a Memory System contrast.

### M6. Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

- **Authors / year:** Prateek Chhikara, Dev Khant, Saket Aryan, Taranjeet Singh, Deshraj Yadav, 2025.
- **Venue / links:** ECAI 2025 Main Track; [DOI / proceedings](https://doi.org/10.3233/FAIA251160) · [arXiv](https://arxiv.org/abs/2504.19413) · [code](https://github.com/mem0ai/mem0)
- **Role / contribution:** Supporting / Memory System
- **Primary dimension:** A5.4.2 Cross-turn State Revision
- **Secondary dimensions:** A5.4.1 Selective Information Persistence; A5.4.3 Future Information Utility
- **Persistence target:** External Memory, using dense vector storage for Mem0 and graph memory for Mem0g
- **Memory failure labels:** Write Failure, Update Failure, Retrieval Failure, Utilization Failure
- **Selective Information Persistence:** GPT-4o-mini prompting extracts salient candidate facts from the current message, summary, and recency window. Mem0g additionally extracts entity/relation triplets with importance, uniqueness, and persistence cues. There are no independent write precision/recall labels or human write-quality annotations.
- **Cross-turn State Revision:** Candidate facts are matched to similar memories and an LLM function call chooses ADD, UPDATE, DELETE, or NOOP. Mem0g can invalidate/tombstone, merge, or retain conflicting relation edges with provenance. These are inference-time operations, not learned memory policies.
- **Future Information Utility:** LOCOMO single-hop, multi-hop, temporal, and open-domain QA provide downstream utility. Mem0g improves some temporal results and the system reduces token/latency cost, but full-context scores higher overall and no oracle-memory or memory-only control is provided.
- **Temporal consistency:** Medium at the architecture level but limited as evidence. Timestamps and graph tombstones support temporal state, yet stale, expiry, preference-change, conflict-order, and selective-forgetting tests are missing.
- **Future utility attribution:** Limited. Gains may come from retrieval, prompting, parametric knowledge, or context leakage rather than a particular persisted memory.
- **Memory policy learning:** Not demonstrated. Function calling, similarity, thresholds, and prompts determine memory actions; there is no action-level supervision, SFT, DPO, PPO/GRPO, or memory-action reward.
- **Evidence vector:** `Method Effectiveness: Medium`; `Capability Isolation: Limited`; `Generalization Evidence: Limited`.
- **Main finding:** Mem0 is a practical lifecycle-oriented Memory System and useful baseline for A5.4, but not evidence that an LLM learned a transferable memory policy.
- **Main limitation:** No causal memory ablation, operation-level correctness benchmark, stale/expiry suite, or cross-environment transfer. The current public repository has evolved beyond the paper and should not be conflated with the historical reported implementation.
- **Decision:** Include Supporting.

## First-batch synthesis

### Measurement

LongMemEval and MemoryAgentBench provide broad evaluation coverage for long-term interaction, incremental memory, temporal reasoning, knowledge update, selective forgetting, and later-task utility. They are measurement resources, not training methods. Neither supplies a complete operation-level audit of write, update, delete, NOOP, retrieval, and utilization.

The complete **No Persisted State → Actual Persisted State → Oracle State** ladder is absent. LongMemEval comes closest through full-history, actual retrieval, and oracle-evidence conditions, but retrieval, reader prompts, time cropping, context leakage, and parametric knowledge remain confounded. The other four works do not provide a complete three-way causal comparison.

### Learning

Memory-R1 is the only first-batch work that clearly updates LLM/Agent Policy parameters with PPO/GRPO for memory lifecycle and utilization. Its action space is well aligned with ADD, UPDATE, DELETE, and NOOP, but its sparse downstream QA reward cannot establish operation-level correctness.

MemRL is an important contrast: it freezes the LLM and learns external-memory Q values and retrieval ranking from runtime feedback. It addresses future utility more directly than the other memory systems, but it does not learn full memory formation, content revision, deletion, expiry, or NOOP behavior.

A-MEM and Mem0 implement useful memory organization and lifecycle operations through prompting, function calling, similarity, and rules. Their results should not be described as learned Persistence Policy Learning. The two benchmark papers also have no training target.

### Generalization and failure attribution

The four failure types must remain separate:

- **Write Failure:** the system fails to preserve information that should be stored or stores irrelevant information;
- **Update Failure:** old state is not correctly overwritten, merged, invalidated, or expired;
- **Retrieval Failure:** the correct memory exists but is not recalled;
- **Utilization Failure:** the memory is recalled but the reader or decision policy does not use it correctly.

Across the six papers, these failures are often mixed. The strongest next experiments should log the memory state and intervene on one operation at a time. They should compare no memory, actual memory, and oracle memory; remove or replace a key memory; change time order; modify user preferences; inject stale or conflicting memories; and control fresh retrieval and parameter knowledge.

The current evidence supports the bounded conclusion that external-memory organization, retrieval, and limited utility learning can improve downstream behavior, and Memory-R1 demonstrates genuine Agent Policy post-training. It does not yet establish a transferable, causally attributed, full lifecycle memory-management capability.

## Scope closure

A5.4 is closed for active expansion. Add a paper only if it directly studies LLM Policy post-training, operation-level credit assignment, counterfactual persisted-state utility, or strict cross-environment generalization. Do not expand into a general Agent Memory architecture survey.
